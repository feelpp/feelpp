== Overview

This document provides a comprehensive prompt for the phased modernization of the `feelpp/feel/feelpoly` module to C++20. The goal is to introduce modern C++ features while maintaining backward API compatibility.

=== Key Objectives

1. **C++20 Concepts**: Replace SFINAE patterns with concepts for cleaner, more expressive code
2. **Replace boost::mpl**: Migrate to C++20 type traits + boost::mp11 for compile-time metaprogramming
3. **Dynamic Order Support**: Add Eigen-style `Dynamic` order alongside static order (dimensions remain static)
4. **Eigen Migration**: Gradually replace ublas with Eigen for linear algebra (Kokkos compatibility)
5. **Backward Compatibility**: Existing API must continue to work without modification

=== Constraints

* C++20 minimum (no C++17 fallback)
* Topological dimension (`nDim`) and spatial dimension (`nRealDim`) remain static template parameters
* Order can be static (default, backward compatible) or dynamic (opt-in)
* Must be compatible with Kokkos kernels (POD types, no virtual functions in hot paths)
* ublas remains default storage for backward compatibility; Eigen is opt-in

// FROM: template<typename Poly, template<uint16_type> class PolySetType = Scalar>

// 1. Add OrderSpec template parameter defaulting to Poly::nOrder (backward compat)
// 2. Add is_order_static constexpr bool = (OrderSpec != Dynamic)

// 4. Add runtime m_order member (only used when !is_order_static)
// 5. Add constructor taking runtime order for dynamic case
// 6. Add toDynamic() method to convert static -> dynamic
// 7. Add toStatic<N>() method returning optional<> for dynamic -> static
// 8. Use concepts to constrain methods (requires is_order_static, etc.)
// 9. Replace BOOST_STATIC_ASSERT with static_assert
// 10. Replace mpl usage with mp11/C++20

== Implementation Guidelines

=== Code Style

[source,cpp]
----
// Use constexpr for compile-time values
static constexpr uint16_type nDim = Dim;

// Use concepts in requires clauses
template<EigenMatrix M>
auto process(M const& m) requires (M::RowsAtCompileTime > 0) { ... }

// Use [[nodiscard]] for getters
[[nodiscard]] constexpr uint16_type dim() const noexcept { return nDim; }

// Use if constexpr for compile-time branching
if constexpr (is_order_static) {
    return nOrder;
} else {
    return m_runtime_order;
}

// Use std::conditional_t instead of mpl::if_
using type = std::conditional_t<Cond, TypeA, TypeB>;

// Use mp::mp_list instead of mpl::vector
using type_list = mp::mp_list<Type1, Type2, Type3>;

// Use mp::mp_at_c instead of mpl::at
using selected = mp::mp_at_c<type_list, Index>;
----

=== Backward Compatibility Checklist

For each modified file, verify:

* [ ] Existing template instantiations compile
* [ ] Existing type aliases resolve to same types
* [ ] Existing static constants have same values
* [ ] Existing methods have same signatures (or compatible overloads)
* [ ] Existing inheritance hierarchies preserved
* [ ] Existing tests pass without modification

=== Performance Considerations

* Use `[[no_unique_address]]` for empty members (e.g., static order storage)
* Prefer `constexpr` functions over type traits for simple computations
* Use fixed-size Eigen types when dimensions are known at compile time
* Avoid virtual functions in hot paths (use concepts for static dispatch)

When implementing these changes:

1. **Read before modifying**: Always read the existing file content before making changes
2. **Preserve structure**: Keep existing class layout and member ordering where possible
3. **Add, don't replace**: Add new overloads/methods alongside existing ones initially
4. **Test incrementally**: Verify compilation after each significant change
5. **Document concepts**: Add brief comments explaining what each concept requires
6. **Use static_assert**: Add static_asserts to verify concept satisfaction where helpful
