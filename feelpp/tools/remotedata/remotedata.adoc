== NAME

{manmanual} - manage remotedata for {feelpp}


== SYNOPSIS

{manmanual} is a simple application which can download data, upload data and print remote data listing from multiple platforms including GitHub, Girder, and CKAN.


== DESCRIPTION

The {manmanual} tool provides a unified interface for managing data across different remote storage platforms. It supports downloading, uploading, and browsing data with comprehensive progress reporting and multiple verbosity levels.

== SUPPORTED PLATFORMS

{manmanual} supports three major remote data platforms:

.Platform Support Matrix
|===
| Platform | Download | Upload | Contents | List Organizations | Authentication

| *GitHub* | ✓ | ✗ | ✗ | ✗ | Token
| *Girder* | ✓ | ✓ | ✓ | ✗ | API Key
| *CKAN* | ✓ | ✓ | ✓ | ✓ | API Key
|===

== OPTIONS

=== Common Options

{manmanual} requires some options.

.Table of command-line {manmanual} options
|===
| Name | Description | Default value

| upload | specify the remote server and the location of uploaded files on remote server |
| download | specify remote data to download |
| data a|

* with upload mode : datas path (file or dir) to upload,
* with download mode : the path of downloaded datas
|
| contents | specify data contents to print in the terminal |
| list-organizations | list available organizations (CKAN only) |
|===

=== Progress and Verbosity Options

.Progress Control Options
|===
| Option | Description

| `--quiet, -q` | Suppress progress output, show only errors
| `--verbose, -v` | Enable verbose progress output
| `--progress` | Show detailed progress information with file sizes
| `--debug` | Enable debug output with full API details and responses
|===

== GITHUB

GitHub integration allows downloading files and folders from public and private repositories.

=== Configuration Options

|===
| Option | Default value | Description

| `owner` | feelpp | the github organization
| `repo` | feelpp | the github repository in organization
| `branch` | <default in github> | the branch in the git repository
| `path` |  <root of repository> | the path in the git repository
| `token` | <no default value> | an authentication token
|===

=== Authentication

GitHub authentication is required for private repositories or to increase API rate limits.

* Environment variable:
+
[source,shell]
----
export FEELPP_GITHUB_TOKEN=xxxxx
----

* Inline token:
+
[source,shell]
----
github:{repo:feelpp,path:README.adoc,token:xxxx}
----

=== Examples

* Download file from GitHub:
+
[source,shell]
----
feelpp_remotedata --download "github:{repo:feelpp,path:README.adoc}"
----

* Download from private repository:
+
[source,shell]
----
feelpp_remotedata --download "github:{owner:myorg,repo:myrepo,path:data/,token:xxxx}"
----

== GIRDER

Girder is a data management platform that provides a web-based interface for storing, managing, and sharing scientific data.

=== Configuration Options

|===
| Option | Default value | Description

| `url` | https://girder.math.unistra.fr | url of a Girder platform
| `file` | <no default value> | one or several file id(s)
| `folder` | <no default value> | one or several folder id(s)
| `item` | <no default value> | one or several item id(s)
| `api_key` | <no default value> | an authentication key
| `token` | <no default value> | a direct authentication token
|===

=== Automatic ZIP Extraction

When downloading folders or items from Girder, the tool automatically handles ZIP archives:

* **Automatic extraction**: ZIP files are automatically extracted without manual intervention
* **Individual file listing**: Shows progress and details for each extracted file rather than just the ZIP
* **Clean file access**: Extracted files are immediately available for use
* **Progress tracking**: Displays extraction progress and lists all extracted files in verbose mode

NOTE: This enhancement provides a seamless experience similar to direct file downloads, eliminating the need for manual ZIP extraction when working with Girder folders and items.

=== Authentication

Girder authentication is required for private data access and upload operations.

* Environment variable:
+
[source,shell]
----
export FEELPP_GIRDER_API_KEY=xxxxx
----

* Inline API key:
+
[source,shell]
----
girder:{folder:5ac72871b0e9574027047894,api_key:xxxx}
----

NOTE: Using api_key is recommended over token as the remotedata app automatically manages token lifecycle.

=== Examples

* Download file from Girder:
+
[source,shell]
----
feelpp_remotedata --download "girder:{file:5b1f8707b0e9570499f66bd0}" --progress
----

* Download folder with automatic ZIP extraction:
+
[source,shell]
----
feelpp_remotedata --download "girder:{folder:5ac72871b0e9574027047894}" --verbose
----
+
This automatically extracts the folder contents and shows individual file progress.

* Download item with automatic extraction:
+
[source,shell]
----
feelpp_remotedata --download "girder:{item:5ac72871b0e9574027047895}" --progress
----
+
Items containing multiple files are automatically extracted and listed.

* Upload data to Girder:
+
[source,shell]
----
feelpp_remotedata --upload "girder:{folder:5ac72871b0e9574027047894}" --data $HOME/mydata
----

* Browse Girder contents:
+
[source,shell]
----
feelpp_remotedata --contents "girder:{folder:5ac72871b0e9574027047894}"
feelpp_remotedata --contents "girder:{file:5b1f8707b0e9570499f66bd0}"
----

== CKAN

CKAN (Comprehensive Knowledge Archive Network) is an open-source data management system used for publishing, sharing and finding data.

=== Configuration Options

|===
| Option | Default value | Description

| `url` | <from environment> | URL of a CKAN instance
| `api_key` | <from environment> | API key for authentication
| `organization` | <from environment> | organization name
| `dataset` | <no default value> | dataset name or ID
| `resource` | <no default value> | resource ID for specific file operations
|===

=== Enhanced Progress Reporting

CKAN downloads now feature enhanced progress reporting:

* **Filename-aware progress**: Shows the actual filename being downloaded instead of just generic progress
* **Real-time updates**: Live progress bars with transfer rates and completion percentages
* **Timeout support**: Configurable timeout handling for robust downloads
* **Detailed progress format**: Progress bars show format like `filename.ext: [=====>] 42.3% (1.81 MB/1.81 MB)`

NOTE: This provides the same comprehensive progress reporting as Girder downloads, ensuring consistent user experience across platforms.

=== Environment Variables

CKAN operations can be configured using environment variables:

[source,shell]
----
export FEELPP_CKAN_URL="https://ckan.example.com"
export FEELPP_CKAN_API_KEY="your-api-key"
export FEELPP_CKAN_ORGANIZATION="your-org"
----

=== Authentication

CKAN authentication is required for private datasets and upload operations.

* Environment variables (recommended):
+
[source,shell]
----
export FEELPP_CKAN_API_KEY=xxxxx
export FEELPP_CKAN_ORGANIZATION=myorg
----

* Inline credentials:
+
[source,shell]
----
ckan:{url:https://ckan.example.com,api_key:xxxx,organization:myorg}
----

=== Examples

* List available organizations:
+
[source,shell]
----
feelpp_remotedata --list-organizations="ckan:{}"
feelpp_remotedata --list-organizations="ckan:{url:https://demo.ckan.org}"
----

* Download entire dataset:
+
[source,shell]
----
feelpp_remotedata --download "ckan:{dataset:my-dataset}" --progress
----

* Download specific resource:
+
[source,shell]
----
feelpp_remotedata --download "ckan:{resource:resource-id}" --debug
----

* Upload data to CKAN:
+
[source,shell]
----
feelpp_remotedata --upload "ckan:{dataset:my-dataset}" --data $HOME/mydata
----

* Browse dataset contents:
+
[source,shell]
----
feelpp_remotedata --contents "ckan:{dataset:my-dataset}"
----

== GENERAL EXAMPLES

=== Download Examples

* Download file from URL:
+
[source,shell]
----
feelpp_remotedata --download https://raw.githubusercontent.com/feelpp/feelpp/develop/README.adoc
----

* Download with custom directory:
+
[source,shell]
----
feelpp_remotedata --download "girder:{file:5b1f8707b0e9570499f66bd0}" --data $HOME/mydir
----

* Download with different verbosity levels:
+
[source,shell]
----
# Quiet mode (errors only)
feelpp_remotedata --download "ckan:{dataset:sample}" --quiet

# Normal mode (default)
feelpp_remotedata --download "ckan:{dataset:sample}"

# Progress mode (detailed progress)
feelpp_remotedata --download "ckan:{dataset:sample}" --progress

# Debug mode (full API details)
feelpp_remotedata --download "ckan:{dataset:sample}" --debug
----

=== Upload Examples

* Upload to Girder:
+
[source,shell]
----
feelpp_remotedata --upload "girder:{folder:folder-id}" --data $HOME/mydata --verbose
----

* Upload to CKAN:
+
[source,shell]
----
feelpp_remotedata --upload "ckan:{dataset:my-dataset}" --data $HOME/mydata --progress
----

=== Browse Examples

* Browse with different platforms:
+
[source,shell]
----
# Girder folder contents
feelpp_remotedata --contents "girder:{folder:5ac72871b0e9574027047894}"

# CKAN dataset contents
feelpp_remotedata --contents "ckan:{dataset:my-dataset}"

# Multiple Girder items
feelpp_remotedata --contents "girder:{folder:[id1,id2],file:id3}"
----

== PROGRESS REPORTING

The {manmanual} tool provides comprehensive progress reporting with four verbosity levels:

.Progress Levels
|===
| Level | Option | Description | Output

| *Quiet* | `--quiet, -q` | Minimal output | Errors only
| *Normal* | (default) | Standard progress | Operation status, file names
| *Verbose* | `--verbose, -v` or `--progress` | Detailed progress | File sizes, transfer rates, detailed status
| *Debug* | `--debug` | Full diagnostic | API requests/responses, URLs, technical details
|===

=== Progress Features

* **File-by-file progress**: Shows individual file download/upload progress
* **Size reporting**: Displays file sizes in human-readable format (KB, MB, GB)
* **Error handling**: Clear error messages with specific failure reasons
* **Operation summaries**: Final status with success/failure counts
* **API debugging**: Full request/response logging in debug mode

== ERROR HANDLING

The tool provides robust error handling:

* **Network errors**: HTTP status codes and connection issues
* **Authentication errors**: Clear messages for invalid credentials
* **Resource not found**: Specific error messages for missing files/datasets
* **Permission errors**: Access denied messages with suggestions
* **Data validation**: JSON parsing errors and malformed responses
