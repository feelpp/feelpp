= SB9 solid-shell applications

This directory contains the SB9 quickstart drivers, their cases, mesh templates,
measurement data, and formulation notes. The variational operators remain in
`feelpp/feel/feelvf/` and their unit tests remain in `testsuite/feelvf/`.
The elasticity case reader, reference checker, and shell benchmark framework
are shared with the standard elasticity applications in the parent directory.

== Applications

* `feelpp_qs_sb9`: static mixed SB9 formulation with reference checks and
  postprocessing, implemented in `qs_sb9.cpp` and `qs_sb9_postprocess.hpp`.
* `feelpp_qs_sb9_mixed_bending`: mixed-bending driver using the specifications
  in `sb9.json`, `sb9_benchmarks.json`, and `sb9_validations.json`.
* `feelpp_qs_sb9_dynamic`: experimental driver with Newmark time integration,
  moved from `research/sb9_dynamic/sb9.cpp`.
* `feelpp_qs_sb9_minimal`: the original minimal formulation, previously named
  `qs_sb9_tmp.cpp`. It is available as an explicit build target and excluded
  from the default build.

The existing static executable and CTest names are preserved.

== Build and run

From the repository root:

[source,shell]
----
cmake --build build/default --target feelpp_qs_sb9 feelpp_qs_sb9_mixed_bending feelpp_qs_sb9_dynamic -j2

build/default/feelpp/quickstart/elasticity/sb9/feelpp_qs_sb9 \
  --config-file=feelpp/quickstart/elasticity/sb9/cases/affine-hexa/affine_hexa.cfg

build/default/feelpp/quickstart/elasticity/sb9/feelpp_qs_sb9_mixed_bending \
  --config-file=feelpp/quickstart/elasticity/sb9/qs_sb9_mixed_bending.cfg

ctest --test-dir build/default -R '^feelpp_qs_sb9-' --output-on-failure
----

The `quickstart` and `check` build targets include the static, mixed-bending,
and dynamic drivers. Build `feelpp_qs_sb9_minimal` explicitly when needed.

== Cases and notes

* `cases/` contains the affine-hexa case, static benchmarks, and validation
  cases. The standard Q1/Q2 elasticity drivers reuse some of these cases.
* `.tests.sb9` registers the static SB9 regression cases.
* `meshes/` contains the rectangular and circular shell templates used by the
  shared shell benchmark framework.
* `docs/` contains the Typst formulation and implementation notes.
* `dynamic/` contains the experimental tank and plate configurations and
  measured load histories.

The experimental dynamic cases require external mesh files, which are not
included in the repository:

* `dynamic/cuve/mesh_cuve_feelpp_ok.msh`
* `dynamic/plaque_pas_percee/plaque_pas_percee.msh`
* `dynamic/plaque_percee/plaque_percee_dx1mm_force_apply.msh`

Place the appropriate mesh beside its configuration or override
`--gmsh.filename`. The dynamic driver currently applies the measured force at
the `force_apply` point marker; the tank case requires adapting this to its
`pt_P1` marker. These measurement cases are not registered as CI tests.

The `qs_add_testcase_elasticity` target copies this directory with the other
elasticity data. Installation places it under
`share/feelpp/data/testcases/quickstart/elasticity/sb9/`.
